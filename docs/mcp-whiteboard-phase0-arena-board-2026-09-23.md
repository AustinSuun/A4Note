# 线索白板与自由白板：Phase 0 讨论方案

> **低优先级长期规划｜未实现功能｜不是开发批准**
>
> 任务 `865d6308-6bef-463c-bbbf-67debe4ea731`，需求版本 1。调研日期：2026-09-23。
> 仓库基线：`fcc204051f8788af079678a59f83bc9618e5c97c`。本阶段只读源码及公开资料，仅交付本文与必要交接状态；未制作原型、安装依赖、修改产品代码/数据库或进行性能实测。

## 1. 结论先行

1. **产品方向可行，但应是一种白板文档、两类使用方式，而不是两个互不兼容的产品。** 空白板可以独立画图、讲课；同一块板按需插入资料卡，逐渐变成线索板。不要强制绑定论文、笔记或 AI。
2. **首个开发版本建议先做可靠的纯白板。** 文本、基础图形、画笔/整笔擦除、图片、箭头、分组、撤销、保存恢复足够形成闭环。资料活引用和结论追踪分阶段加入；“几乎所有数据”不是首版承诺。
3. **现有应用有可复用的资源身份、文件会话、文献/笔记/标注模型和导航，但没有已核实的通用白板存储或任意关系写入闭环。** `KnowledgeObject/Relation` 类型的存在不等于已具备跨资料永久关系数据库。
4. **技术建议是条件式的。** 如果先低成本验证普通白板，优先评估 Excalidraw 嵌入；如果首要价值是深度自定义活资料卡，优先评估自有语义模型＋Canvas/DOM 混合画布，或在预算许可时评估 tldraw。不要先选库，再被库的元素模型限制产品。
5. **性能尚未实测。** 大图解码、长笔迹、复杂文本卡和密集连线比“画布面积无限”更难。先以中等规模为候选验收目标，超大规模设计降级，不承诺无限承载。
6. 本文提交待讨论之后应当停止。**后续任何原型、依赖引入、迁移或开发任务，都需要用户另行批准。**

## 2. 产品边界与典型流程

### 2.1 四个场景

| 场景 | 典型流程 | 成功标准 |
| --- | --- | --- |
| 独立普通白板 | 新建空白板 → 写字/画图/粘贴截图 → 连线分组 → 保存 → 重新打开 | 不要求选论文或项目资料，不依赖网络，图形与图片完整恢复 |
| 探案式线索整理 | 从资料发送卡片 → 写假设 → 用“支持/反驳/待核查”等标签连线 → 打开来源核实 → 形成结论卡 | 用户能区分原始材料、自己的解释、尚未证实的推断 |
| 讲课/演示 | 课前排好主题区 → 聚焦某一区域 → 临时画笔/指示 → 导出讲义或保存修改 | 平移/缩放不误改内容，退出演示可回到编辑，原始板不被临时演示意外覆盖 |
| 发散思考与总结 | 便签自由排布 → 多选聚类 → 命名主题区 → 抽取摘要/结论 | 从无结构思考逐渐整理，不强制先定义图谱结构 |

### 2.2 分级功能矩阵

“首版必需”指未来获批后的 Phase 1，不是本次要实现的内容。

| 能力 | 首版必需 | 后续可选 | 远期/明确限制 |
| --- | --- | --- | --- |
| 白板文档 | 新建、命名、打开、保存状态、关闭重开、损坏提示 | 模板、最近访问、回收站 | 多人同时编辑不是首版 |
| 画布 | 平移、缩放、适配内容、复位、选择工具 | 小地图、书签视口、网格吸附 | 不承诺任意大坐标与无限精度 |
| 文本/便签 | 中文输入、换行、字号/颜色、基本编辑 | 富文本、清单、公式 | 不把完整 Markdown 编辑器挂到每张卡上 |
| 基础图形 | 矩形、椭圆、线段、箭头；移动/缩放/旋转 | 更多形状、对齐分布、组合样式 | 不做 CAD 或专业矢量排版 |
| 自由画笔 | 鼠标画线、粗细/颜色、整笔擦除 | 笔压、分段擦除、触控笔按钮 | 笔压与掌触抑制必须在真实设备验证 |
| 选择/组织 | 多选、框选、复制/粘贴、删除、分组、前后层级 | 锁定、套索、主题区/框架 | 视觉分组不自动成为知识关系 |
| 图片/截图 | 粘贴和文件选择导入、本地持久副本、缩放 | OS 拖入、裁切、重连丢失资源 | 不默认实时录屏或全盘图片扫描 |
| 连线 | 绑定两端的直线/箭头，随对象移动 | 标签、曲线、正交路由、关系筛选 | 自动布局不是手工推理的替代 |
| 撤销/恢复 | 一次手势一次撤销、重做、保存失败恢复 | 历史快照、版本比较 | 不允许撤销白板操作顺带改回原文 |
| 资料接入 | 暂不要求 | 整篇笔记/文献/PDF/标注卡、搜索插入、来源跳转 | 段落稳健锚点、任意插件/任务/AI资料分批验证 |
| 线索与结论 | 普通文本和连线可先表达 | 证据/结论卡、支持/反驳、来源清单、待核查状态 | 不默认自动推理或事实判定 |
| 演示/导出 | 至少可恢复的源文档；PNG 可列入首版收尾 | 只读演示、框架顺序、临时指示、SVG/PDF、脱敏导出 | 不承诺录课/协作直播；导出不是可编辑备份 |

**非目标：** 首版不做在线协作、云同步、移动端完整适配、自动知识图谱、OCR 全库索引、自动 AI 结论、任意网页/Office 内嵌编辑，不改现有笔记或 PDF 的编辑协议。

### 2.3 一个容易忽略的交互约定

空格拖动画布与文本输入不能争抢键盘；Esc 退出当前工具，Delete 只作用于白板选择；画笔/橡皮必须有明确工具状态。双击资料卡默认打开来源而不是修改原文；卡片菜单再提供“刷新”“冻结为快照”“查看来源”。提供键盘可访问的对象列表与属性面板，不能只依赖 Canvas 命中测试。

### 3.2 三条对实现有直接影响的核实结果

1. `src/core/relations.ts/buildPaperKnowledgeGraph` 根据一个 PaperDocument **派生**关系图，`getObjectNavigationTarget` 只覆盖有限种类。`src-tauri/schema.sql` 未发现通用 knowledge/relations/whiteboard 表。因此本方案不能声称现有后端已经能持久化用户画出的任意语义边。
2. 图映射中有系统生成的附属/摘录关系；例如对首篇笔记生成的 `excerpted_from` 关系不应直接解释为用户逐条确认的证据来源。白板证据引用必须保存用户实际选择的来源，不把展示用关系自动变成事实断言。
3. `listNativePapers()` 会调用 `provisionLibrarySummaries()`。虽然名字像读取，实际上存在补建摘要的流程。未来只读资料解析器应复用已加载数据或新增无副作用的查询边界，**不能为白板预览无条件调用它**。本次没有调用这个接口。

## 4. 活引用、快照与来源语义

### 4.1 三种明确模式

| 模式 | 保存什么 | 原文变更时 | 适用场景 |
| --- | --- | --- | --- |
| 活引用 | 类型化 locator、稳定来源 ID、解析版本、最近预览缓存 | 标示“来源已更新”，用户可刷新；不静默改变已经写出的结论 | 文献/笔记导航、随内容维护的资料板 |
| 冻结快照 | 插入时内容/图片副本、时间、来源 locator、可选 hash | 快照保持不变，仍可打开当前原文；标示与原文不同版本 | 证据、课程讲义、引用当时状态 |
| 白板原生内容 | 文本/笔迹/形状及用户关系 | 无外部来源依赖 | 独立白板、假设、解释、结论 |

建议资料卡默认“活引用＋最近一次有界缓存”，证据摘录默认冻结快照；每张卡可见模式，不用一个模糊“嵌入”按钮隐瞒差别。整篇文档默认只显示有界摘要/缩略图，展开或回源后再读更多，避免复制全部正文。

### 4.2 更新、删除、移动与回跳

- 来源被修改：卡片显示更新状态及版本时间；自动刷新仅可用于用户明确开启的预览，结论保持用户版本。
- 来源删除/项目移除：卡片成为“来源不可用”，保留布局和已有快照；禁止静默删卡或自动重建来源。Resource 的项目级级联生命周期意味着 locator 还应保留可理解的来源说明。
- 白板删卡：只删白板实例，不删原文/标注。删除整板亦不能删除被其他白板或用户文件使用的资产。
- 应用内移动/改名：未来解析器订阅路径迁移并更新 locator；不能只依赖当前文本会话迁移。应用外移动先标记失联，提供用户选文件重连；hash 只是候选依据，不能自动关联任意同名文件。
- 段落定位失败：依次尝试受支持的稳定块 ID、文本及前后文匹配，最后回到文档并提示未定位。不得高亮一段相似但错误的文字，冒充精确定位。
- 回跳只通过现有资源 opener/受控导航能力；未知协议和外部可执行文件不能自动打开。URI 与显示标题分离，导出时不默认暴露绝对路径。
- 反向链接先在白板自己的引用索引里登记。“哪些板引用了这篇笔记”不要求修改原 Markdown；全局跨板索引属于后续能力，不伪称已有。

### 4.3 本地资产与隐私

建议资产按内容 hash 去重、使用资产 ID，不在每次保存与撤销历史中重复塞 Base64。导入产生白板托管副本时必须说明；“只引用原图”则明确可能失联。资产垃圾回收需覆盖已保存板、撤销历史、恢复日志和回收站的可达集合，并延迟删除，不在最后一张可见卡消失时立即删文件。

对超大图/异常压缩图片设置像素数和字节上限；SVG/HTML 清洗或安全栅格化；不自动联网抓取 URL 预览、执行本地脚本或装载远程 iframe。离线可用不等于已加密；本阶段不承诺静态加密。导出可选择去掉来源路径、私人备注、AI 提示和缓存正文，并列出外链与嵌入副本的差别。白板资产需要纳入未来备份/恢复设计，不能假设现有资料库备份会自动包含新目录。

## 5. 线索、关系与结论：用户主导

建议使用普通卡、证据卡、假设卡、结论卡四种语义，可逐步启用，不限制同一来源在多个主题区出现。

- **视觉连线**只有排布意义；**语义关系**才有方向、标签、说明、创建者和时间。两者分开保存，防止随手画线污染知识关系。
- 支持、反驳、补充、时间先后、同一对象、待核查可作初始标签；允许自定义文字。标签表达的是用户判断，不是系统认证。
- 结论卡包括结论正文、依据列表、反例/缺口、状态（草稿/待核查/用户确认）和来源版本。多个证据可以支持一个结论，也可以相互矛盾。
- 用户把笔记观点写到结论卡，并不等于引用已经正确。应可从每项依据回到引用片段和来源，而非只能回到整板。
- 分组表示视觉区域；主题区表示组织范围；需要语义关系时用户显式创建。移动进一个框不自动建立“证明”关系。

**AI 仅远期可选：** 用户选定范围后生成候选摘要/连线，逐条确认；必须保留引用片段、来源版本、模型生成标识和失败状态。不得把推测改写成事实。涉及发送正文、截图或私人资料时，应先列出发送范围、供应商/离线选项及费用，默认关闭。没有证据链时不生成“已证实”标签。

## 6. 技术路线比较

### 6.1 当前技术条件（F）

仓库使用 React 19、TypeScript 6、Vite 8、Tauri 2/Rust、rusqlite；Markdown 使用 CodeMirror/ReactMarkdown，PDF 使用 pdfjs-dist（依据 package.json、src-tauri/Cargo.toml）。当前依赖表未列出 Excalidraw、tldraw、React Flow 或 Konva。本阶段未安装它们，**React/WebView2 兼容性与打包效果均未验证**。

| 维度 | A：嵌入 Excalidraw | B：自有模型＋混合渲染 | C：tldraw SDK |
| --- | --- | --- | --- |
| 适合优先验证什么 | 纯白板、教学、截图＋图形 | 深度资料卡、证据语义、长周期可控演进 | 自定义资料卡与完整画布编辑器的折中 |
| 渲染与交互 | 官方描述为 canvas-based；已有绘图、擦除、连线、撤销等工具 | Canvas2D 绘制笔迹/图形/连线，少量 DOM 承载编辑中的文字/资料卡；可选 Konva 辅助 | ShapeUtil 定义自定义形状的呈现/几何/交互，可用 HTMLContainer；具体 WebView 表现待验证 |
| 数据模型 | 尽量不 fork 核心；原生 scene 与白板语义 sidecar 建立稳定映射 | 自有 Board/Element/Connection/SourceRef/Asset 模型，渲染器可替换 | SDK store/shape/asset/binding 加自有 sourceRef 元数据及迁移 |
| 内部资料卡 | 优先图片/摘要快照＋来源链接；复杂交互卡可能受元素扩展边界限制 | 可精确控制预览、引用失效、证据版本；需要自己实现命中、变换、文本编辑 | 定制卡片较自然，但必须验证持久化、复制粘贴、导出、移动端输入是否保留语义 |
| 保存/撤销 | 有撤销与 JSON 导出；Aster 仍负责持久化、附件和故障恢复 | 命令/补丁历史、事务化手势、增量日志全部自建 | SDK 提供 store/形状体系；本地原生存储桥接、资产寿命和退出保存仍由应用负责 |
| 许可 | MIT，保留版权和许可文本；具体采用版本与传递依赖需锁定审计 | 自有代码；可选 Konva 为 MIT，仍需审计字体/其他依赖 | 非宽松开源 SDK 许可；生产需要有效许可，商业/爱好用途条件不同 |
| 主要风险 | 深度 fork 后升级困难；sidecar 在复制/导入/元素重建时失配；网站功能不能当作 npm 包内置 | 开发量最高；IME、触控、橡皮、几何与历史系统都可能低估 | 授权成本/分发条件/续期与离线部署约束；SDK 数据模型绑定 |
| 维护成本判断（S） | 普通白板低至中；深度改造升为高 | 初期高，领域控制最强但测试责任永久存在 | 中等工程成本＋持续许可与上游兼容成本 |

**公开依据：** Excalidraw 官方 README 列出图片、PNG/SVG/JSON 导出、自由绘制、橡皮、箭头绑定、撤销、缩放平移，并明确其网站的协作、浏览器自动保存等与 npm editor 功能有区别：[官方说明](https://raw.githubusercontent.com/excalidraw/excalidraw/master/README.md)、[MIT 许可](https://raw.githubusercontent.com/excalidraw/excalidraw/master/LICENSE)。tldraw 自定义形状依据[官方 Shapes 文档](https://tldraw.dev/docs/shapes)；其生产许可及离线 license key 规则依据 [2](https://tldraw.dev/community/license)。Konva 的 MIT 依据[官方 LICENSE](https://raw.githubusercontent.com/konvajs/konva/master/LICENSE)。均为 2026-09-23 在线查阅，不是已锁定依赖或法律意见，立项时须再次核对选定版本与分发条款。

### 6.2 为什么不直接选“关系图编辑器”或 WebGL

React Flow/xyflow 的核心定位是节点式界面，可作为“资料卡＋边”的候选，官方仓库许可为 MIT（[仓库](https://github.com/xyflow/xyflow)、[LICENSE](https://raw.githubusercontent.com/xyflow/xyflow/main/LICENSE)）。但本任务还要笔迹、橡皮、自由图形、旋转与讲课；不能因关系图方便就假定这些交互齐全。若采用它再叠加绘画层，两个选择/坐标/历史系统的同步成本可能抵消收益，建议只在“线索板优先、普通绘画很轻”的条件下进一步评估。

SVG 适合清晰连线与导出，但大量 DOM 元素/复杂路径会有布局与事件成本；Canvas2D 适合批量图元，文本编辑和可访问性需要 DOM 配合；WebGL 对大规模绘制有潜力，但文本、命中、导出、纹理生命周期和上下文丢失更复杂。**WebGL 是性能证据驱动的后续选择，不是“无限画布”的先决条件。**

### 6.3 条件式推荐与下一次批准的范围

- 用户若说“先有一个好用的普通白板，资料卡先简单”：优先 **A**，未来只批准一个有期限的兼容性/扩展性验证阶段；重点检查中文输入、Tauri 离线资源、资产恢复、复制粘贴与来源 sidecar。
- 用户若说“核心就是软件资料自由组合、活引用与证据链”：优先比较 **B 与 C**；若不接受商用 SDK 许可费用，倾向 B，并接受更长工期。
- 无论选哪条，先用文档确定同一个来源语义和导出/迁移约定。避免 A 做出的板未来无法迁移，也不要为降低短期成本设计两套互不兼容的白板。
- 目前**不建议最终锁定库**：本阶段没有做集成实验，无法证明哪一个满足性能、文本与扩展要求。

## 7. 建议架构与持久化契约（S，未实现）

### 7.1 模块边界

未来可设 `features/whiteboard` 管交互，纯类型/命令放 core 的白板模块，文件/SQLite/缩略图通过 platform 适配，原生实现按职责进入 Rust 模块。资料来源通过只读 resolver 接口接入，不能从白板直接 import 阅读器内部组件或绕过 platform 读库。工作台通过既有 scene/resource opener 注册与稳定资源 key 接入，不在 App.tsx 堆分支。

独立板可以不关联任何资料，身份仍可由工作台承载。建议开始时只提供单板编辑标签，不增加第二套窗口/停靠系统。插件型注册不意味着不受权限限制。

### 7.2 数据职责分离

| 记录 | 建议职责 |
| --- | --- |
| Board | 稳定 ID、标题、schemaVersion、元素清单/分块索引、资产索引；视口偏好与内容分离 |
| Element | 独立实例 ID、类型、几何/层级/样式、内容或资产引用；同一来源可有多个实例 |
| Connection | 两端元素 ID、端口/锚点、视觉路径；可选语义标签、说明、创建者 |
| SourceRef | 命名空间、来源类型、source ID/URI、片段定位、来源版本、live/snapshot 模式、失效状态 |
| Asset | hash/ID、MIME、大小/像素尺寸、本地托管位置、缩略图；不把真实机器路径作可移植主键 |
| History/Recovery | 有界可逆补丁或事务日志、检查点、最后持久序号；不重复保存巨大图片字节 |

建议首期采用**版本化 JSON 清单＋伴随资产目录**作为可检查的本地文档；可移植导出包另行封装。SQLite 可后续保存白板目录、搜索与反向引用索引，不必让整个画布每次跟随工作台快照重写。替代方案是 SQLite 增量文档库＋外部资产：跨板查询方便，但备份、迁移和可移植性成本更高。最终存储选择需要用户决定“文件可携带”与“全局资料库管理”的优先级。

保存建议：内存事务 → 可恢复增量日志 → 延迟合并清单，临时文件写完再原子替换；资产先落盘再提交引用，失败时保留草稿并显示未保存，不能先显示“已保存”。外部修改采用版本/预期 hash 检查，冲突时保留两份而不是无条件覆盖。每次指针移动只更新内存，手势结束才形成一个撤销事务。

未知新版本先只读打开/导出原始数据；迁移前备份，失败不覆盖原文件。导入包防路径穿越、绝对路径、解压炸弹与未知可执行内容。第一版无需 CRDT；将来若加协作，应单独设计并发语义，不能把本地撤销协议当多人一致性协议。

## 8. 性能专项：候选目标，不是实测结果

### 8.1 为什么“图片数”不能单独决定规模

4000×3000 的 RGBA 解码图约为 48 MB（45.8 MiB），100 张仅一份像素数据约 4.47 GiB，尚不含纹理、缓存和中间副本。PNG/JPEG 磁盘大小远小于解码内存，不能拿文件压缩比预测运行内存。因此需要按原始像素、可见图数量、纹理预算、笔迹点数和边密度共同分级。

### 8.2 候选测试机器与规模

以下建议以 **Windows 11、16GB RAM、近年四核以上 CPU、集成 GPU、SSD、1080p/60Hz、发布态 WebView2** 为参考；记录具体硬件、DPR、驱动和 WebView 版本。不是本次已经使用的性能测试环境。

| 候选级别 | 合成数据组合 | 候选体验目标 |
| --- | --- | --- |
| S：日常板 | 200 元素、150 边、10张12MP图、2万笔迹点；视口约50张卡 | 冷恢复≤1.5秒；交互帧时间P95≤20ms；指针反馈P95≤50ms；增量工作集≤200MiB |
| M：工作板 | 2000 元素、2000 边、100张12MP图、20万笔迹点；视口150卡，活预览同时≤20 | 冷恢复≤3秒；拖动/缩放帧时间P95≤33ms；反馈P95≤80ms；增量工作集≤500MiB |
| L：压力探索 | 10000 元素、20000 边、300张12MP图、100万笔迹点；刻意制造密集可见区 | 首屏占位≤2秒、可用恢复候选≤10秒；允许LOD后争取≥24fps；超过预算提示并降级，不作为首版承诺 |

这些是**候选门槛而非兼容性保证**，特别是密集可见卡片与密集边可能需要下调规模。L 级用于寻找拐点和拒绝/降级阈值，而不是在产品中写“支持万级对象”。

附加候选指标：S/M 的普通手势结束后持久化P95≤1秒，前台同步工作≤16ms；普通撤销反馈P95≤100ms；图片导入单独显示进度；历史内存候选上限64MiB，纹理/解码缓存候选预算128–256MiB，数值需实测校准。记录文档清单大小、原图总量、缩略图、日志写放大和磁盘不足行为；不能仅验帧率。大文件不应每秒全量重写，备份暂存空间也需纳入磁盘预算。

### 8.3 压力场景与策略

| 压力来源 | 建议策略 | 降级/失败行为 |
| --- | --- | --- |
| 超大画布但对象稀疏 | 世界坐标与屏幕坐标分离，空间索引＋视口余量裁剪，限制极端坐标 | 定位到内容、分区/分页；不为“无限面积”分配巨型位图 |
| 密集资料卡 | 远处只画标题/色块，近处摘要，选中后才挂编辑器；有界可见订阅 | 隐藏复杂预览，保留标题与回跳；卡片失效不拖垮整板 |
| 密集连线 | 空间索引过滤，拖动中直线/低精度路由，结束后计算；按视口和缩放显示标签 | 暂隐藏边标签/非选中关系，提供聚焦子图；不能静默删除边 |
| 长笔迹与橡皮 | 采样合并、按缩放简化显示路径、空间命中索引；原始数据与简化缓存分离 | 先整笔擦除，延后局部擦除；大路径分段，异步处理但不丢原始笔画 |
| 多张高分辨率图片 | 原图磁盘托管、多级缩略图、限制并发解码、按视口懒加载、LRU释放 | 占位图/低清图、手动加载原图；解码失败可重试/替换，超限明确拒绝 |
| 大量引用更新 | 按来源ID合并查询、版本缓存、批处理、取消不可见请求 | 保留带时间的缓存并标示过期；不要轮询全库 |
| 保存与撤销 | 手势事务、补丁日志、有界历史、检查点后台压缩 | 保存失败保留恢复数据；磁盘不足进入明确未保存状态，允许导出救援 |
| GPU/网络/资源异常 | 释放纹理/对象URL，取消工作任务，恢复时按需重建 | 上下文丢失可切低质量渲染；离线不启动远端预览，板本体继续可用 |

### 8.4 不影响阅读器和笔记的隔离要求

`src/workbench/TabHost.tsx` 明确让所有打开标签保持挂载，只用 CSS 隐藏。**隐藏不等于停止渲染和监听。** 未来白板应使用真实 active 状态暂停 RAF、几何计算、预览订阅和无关后台任务，释放可恢复的 GPU 缓存，后台板仅保留模型/待保存队列。工作台快照只保存轻量标签状态，不塞全量画布。

未来测试必须包含“开白板→切PDF滚动→切Markdown输入→回白板”，并与未开白板时对照。候选要求：非活跃白板不持续 RAF、不占输入焦点；阅读/输入延迟相对基线P95退化不超过10%或预先约定的绝对阈值。后台持久化仍要完成，不能为省CPU丢草稿。

### 8.5 未来验证计划（本次没有执行）

1. 用户批准后先建立同一合成数据集，对候选路线做相同场景，不使用真实私人资料。
2. 测冷/热打开、重开/崩溃恢复、持续平移缩放、拖动100个对象、密集连线重算、长笔迹擦除、图片导入、100次撤销、删除/重连引用。
3. 主题、100/125/150%缩放、DPR、鼠标/触控板/真实触控笔、中文IME、键盘导航与 reduced-motion 分别覆盖；不拿桌面鼠标模拟声称笔压已验证。
4. 至少多轮重复，报告中位数/P95/最坏值及冷热缓存条件；记录JS heap、进程工作集、可测GPU内存、long tasks、帧时间、保存字节/耗时、错误日志。工具无法准确测GPU时明确标注，不把JS heap当总内存。
5. 注入缺图、未知schema、断电式中断、磁盘满、路径权限不足、来源被删、并发外部编辑，验证不会静默损坏或覆盖。
6. 设停止条件：超过内存预算、连续长任务或恢复失败则先减载/改方案，不靠取消断言或换高配机制造通过。

## 9. 分阶段路线与粗略工作量

估算是**工程人周，不是日历承诺**；假设1名熟悉仓库的全栈工程师、已有设计决策、Windows优先、本地单用户、无复杂协作/移动端/AI，包含基本自动化测试与恢复处理。授权沟通、产品反复和平台兼容可能增加30%–50%；各阶段区间相关，不能直接相加当固定总价。

| 阶段 | 建议交付 | 依赖/停止门槛 | 粗略区间 |
| --- | --- | --- | --- |
| Phase 0：本次 | 需求/源码核实/路线/候选性能/决策清单 | 用户讨论，不进入实现 | 已交付方案，不估成开发完成 |
| Phase 1A：获批后的有限验证 | 离线嵌入、中文输入、资产持久化、1种自定义资料卡/快照迁移、S/M样本 | 单独授权原型与依赖；许可/数据丢失/扩展边界不通过则停止 | 1–3人周 |
| Phase 1B：最小纯白板 | 第2节首版闭环，资产与恢复、撤销、键盘、必要导出 | 选定路线；稳定保存优先于丰富工具 | A约4–7；B约8–14；C约5–8人周，均不含1A |
| Phase 2：资料接入 | 先文献/整篇笔记/PDF/标注；只读resolver、来源回跳、失效与冻结快照 | 不读写混用，删除/移动/图层边界有测试 | 4–7人周；稳定段落活引用另估2–4 |
| Phase 3：线索与结论 | 标签关系、主题区、证据/结论版本、反向引用、来源清单导出 | 不能把派生关系当永久事实；先确定关系存储 | 3–6人周 |
| Phase 4：长期扩展 | 演示序列、复杂导出、更多适配器、超大规模、可选AI | 每项另立范围、隐私与性能门槛 | 不合并成一个固定估算 |

**顺序比较：**
- 推荐“纯白板→资料→证据组织”，较快验证讲课/思考场景，风险是早期库选择限制后续资料卡；用1A的资料卡与迁移验证降低这一风险。
- “线索卡→基础绘画”更快验证独特价值，但更容易把产品做成关系图工具，普通白板体验延后；适合用户明确把线索整理放首位。
- 不建议两套引擎并行建设后再合并，除非验证证明统一模型不可行且用户接受长期双重维护。

## 10. 风险与需要用户决定的事项

| 风险 | 优先处理 |
| --- | --- |
| 产品同时追求绘画、知识图谱、演示和AI，范围失控 | 先选择一个首发核心场景，工具与接入类型逐阶段白名单 |
| SDK扩展性/许可条件与预期不符 | 采用版本锁定、许可审计与有限验证；不先深度fork |
| 文件迁移或删除后引用失效 | 稳定ID＋来源模式＋可见失效＋用户重连；不自动猜测 |
| 大图导致内存暴涨 | 按像素配额、缩略图与缓存预算，首版就设计资产管线 |
| 保存/撤销造成不可逆丢失 | 原子替换、版本检查、恢复日志、资产可达性和故障注入 |
| 资料外泄或AI误导 | 本地默认、远程请求显式同意、导出脱敏、事实/推断分开 |
| 隐藏白板拖慢其他标签 | active生命周期、暂停任务、内存预算与跨场景基线回归 |

建议用户下一次只决定这些问题，不必一次敲定全部工具：

1. 首发优先：**普通白板/讲课**，还是**软件资料线索板**？建议普通白板先行，但先验证资料卡扩展边界。
2. 是否接受商用 SDK 许可费用及其分发条件？若不接受，排除以生产许可为前提的路线C。
