# Aster 阅读器第一版功能基线

本文档定义阶段 2 的阅读器功能基线。阶段 2 的目标不是把阅读器做成完整 Zotero / Obsidian，而是先建立一个可用、可扩展、界面方向明确的 PDF 阅读场景。

## 1. 阅读器定位

阅读器第一版定位为：

```text
Zotero-like PDF 阅读
+ Obsidian-like 多笔记
+ 统一右侧阅读辅助抽屉
+ 原文/译文并排同步
+ PDF 标注和笔记引用回跳
```

阅读器不是独立知识库系统，也不是完整 AI 阅读代理。它服务当前文献的阅读、标注、笔记和轻量辅助。

## 2. 阅读对象

第一版只支持 PDF。

支持三种阅读模式：

```text
原文 PDF
译文 PDF
原文 PDF / 译文 PDF 并排
```

暂不支持：

- 网页阅读。
- EPUB。
- Word。
- 图片文档。
- Markdown 作为主阅读对象。

Markdown 在本阶段只作为笔记编辑对象，不作为阅读器主阅读格式。

## 3. 原文与译文

译文 PDF 第一版通过手动导入。

导入方式：

- 用户在当前原文 PDF 所属文献中导入译文 PDF。
- 译文 PDF 与原文 PDF 绑定到同一篇文献。
- 一个文献可以绑定多个译文 PDF，但第一版 UI 优先支持选择一个当前译文。

默认假设：

- 原文 PDF 和译文 PDF 页码一致。
- 原文 PDF 和译文 PDF 段落位置、版式排布一致或基本一致。
- 因此第一版不做复杂页码映射、段落对齐或语义对齐。

并排同步：

```text
锁定同步开启：左右 PDF 页码、缩放和滚动位置同步。
锁定同步关闭：左右 PDF 可以独立滚动。
```

## 4. 阅读布局

阅读器使用：

```text
主阅读区 + 统一右侧阅读辅助抽屉
```

不要为每个功能创建独立侧边栏。右侧只保留一个统一抽屉，抽屉内部通过 tab 或分段控制切换功能。

推荐抽屉 tab：

```text
笔记
AI
引用
```

说明：

- 默认关闭右侧抽屉，保持专注阅读。
- 用户点击“随手记”打开笔记 tab。
- 用户点击“AI”打开 AI tab。
- 用户点击“引用”查看当前文献相关引用和低频索引。
- 抽屉关闭后回到专注阅读。

标注索引不作为高频主入口，不单独占一个主要 tab。可以作为“引用”中的低频功能。

## 5. 笔记

笔记采用 Markdown 底层存储，但编辑体验目标接近 Obsidian 的所见即所得。

第一版支持：

- 一篇文献可以有多个 Markdown 笔记。
- 每篇文献默认创建一个主笔记。
- 用户可以手动新建笔记。
- 新建笔记默认绑定当前文献。
- 笔记可以插入 PDF 标注引用。
- 点击标注引用可以回跳到 PDF 对应位置。

第一版不做：

- Obsidian 式完整双链。
- 全局反向链接。
- 知识图谱。
- 跨文献复杂笔记网络。

## 6. 标注工具

阶段 2 的长期目标是支持完整标注工具：

```text
高亮
下划线
删除线
批注
便签
区域框选
自由画笔
形状
箭头
```

实现可以分任务逐步完成，但设计和数据结构应考虑这些工具。

第一版标注要求：

- 标注直接显示在 PDF 上。
- 标注可以编辑。
- 标注可以删除。
- 标注支持撤销/重做。
- 标注支持颜色。
- 原文 PDF 和译文 PDF 标注按 `file_id` 隔离。
- 所有标注都能被回跳定位到 PDF 对应位置。

第一版不做：

- 标注分类。
- 标注筛选。
- 标注导出。
- 面向所有标注的高频列表管理。

## 7. 标注引用

标注可以在笔记中以特殊 Markdown 标记保存。

建议底层格式：

```md
@annotation(annotation-id)
```

编辑器或预览层显示为胶囊或图标，例如：

```text
标注 · 第 5 页
```

点击后：

```text
跳转到 PDF 对应页
定位并高亮对应标注
```

设计原则：

- 不强制把标注全文插入笔记。
- 不使用 `[[annotation:xxx]]`，避免和 Obsidian 双链语义混淆。
- 后续可以扩展同类引用，例如 `@paper()`、`@page()`、`@note()`。

## 8. 标注索引

标注索引是低频功能，不是主工作入口。

第一版可以支持：

- 在“引用”tab 中显示简单文字型标注索引。
- 文字型标注包括高亮、下划线、批注等。
- 点击索引项回跳 PDF。

第一版不要求：

- 显示所有自由画笔、形状、箭头。
- 标注筛选。
- 标注分类。
- 标注导出。

用户主要应该直接在 PDF 上查看标注，而不是通过列表管理所有标注。

## 9. AI 辅助阅读

AI 在阶段 2 中只作为可收起辅助面板。

第一版要求：

- 可以从阅读器右侧抽屉打开 AI tab。
- AI 面板的 UI 形式可以和笔记面板接近。
- AI 面板默认不读取当前页。
- AI 不强制绑定具体标注。
- AI 不需要与标注发生交互。

待后续讨论：

- AI 是否读取当前文献全文。
- AI 是否读取当前笔记。
- AI 是否读取用户选中文本。
- AI 是否支持用户手动添加上下文。
- AI 回复是否需要绑定为知识对象。

阶段 2 不把 AI 辅助阅读做成完整智能阅读代理。

## 10. UI 方向

阅读器 UI 的组合方向：

```text
PDF 阅读部分更像 Zotero。
笔记部分更像 Obsidian。
工作区组织可以借鉴 VS Code。
最终必须符合 Aster 自己的 UI 准则。
```

具体原则：

- 阅读空间优先。
- 工具栏紧凑。
- 右侧抽屉可收起。
- 不把所有功能堆在顶部。
- 标注工具清晰但不喧宾夺主。
- 笔记和 AI 都是随手启用、用完收起。
- 视觉低噪音、高密度、专业。

## 11. 阶段 2 最小闭环

阶段 2 最小闭环定义为：

```text
打开文献
-> 进入 PDF 阅读器
-> 切换原文 / 译文 / 并排
-> 并排时可锁定同步滚动
-> 创建 PDF 标注
-> 在笔记中插入 @annotation(id)
-> 点击笔记引用回跳 PDF 标注位置
-> 打开/收起右侧阅读辅助抽屉
-> 在笔记 / AI / 引用 tab 之间切换
```

只有这个闭环稳定后，再进入更复杂的标注工具、阅读器视觉细化和 AI 辅助阅读增强。

## 13. 阶段 2 必做范围

阶段 2 必须完成：

- 明确阅读器 UI 方向，避免后续继续把功能堆到顶部工具栏。
- 拆分 `PdfReader.tsx` 内部文件边界，让渲染、文本层、标注层和交互 helper 可以分别维护。
- 保持现有 PDF 渲染、页码跳转、缩放、标注创建、编辑、删除、撤销/重做和 `file_id` 隔离行为不回退。
- 将右侧抽屉的产品方向收敛为笔记 / AI / 引用，标注索引作为低频引用能力。
- 完成一轮阅读器低噪音视觉调整，使 PDF 主阅读区优先。

## 14. 阶段 2 不做范围

阶段 2 不做：

- 不重写 PDF.js 渲染策略。
- 不替换 PDF 渲染库。
- 不做 OCR、自动翻译 API、复杂页码映射或段落语义对齐。
- 不做完整 Zotero 级标注管理、筛选、分类和导出。
- 不做完整 Obsidian 双链、全局反链和知识图谱。
- 不把 AI 做成自动阅读代理。
