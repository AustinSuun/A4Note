# Aster UI 设计与实现指南

本文档用于保证 Aster 的界面在多人开发时保持一致。目标不是做营销页面，而是做一个现代、安静、专业、适合长时间使用的知识工作台。

## 1. 总体方向

Aster 的 UI 应接近：

- VS Code / Obsidian 的工作台结构。
- Zotero 的文献和 PDF 工作流效率。
- 更轻、更现代、更适合学生使用的视觉语言。

关键词：

```text
专业
克制
高密度
低视觉噪音
阅读空间优先
状态清晰
键盘可用
可撤销
可扩展
```

## 2. 不做什么

不要做：

- 营销式首页。
- 大面积 hero。
- 大卡片堆叠的展示页。
- 过多装饰渐变和图形。
- 线条很多的传统后台表格。
- 只有一种颜色深浅变化的单调界面。
- 把所有功能都堆成顶部按钮。

## 3. 布局原则

场景切换：

- 左侧窄栏保留。
- 场景入口尽量用图标和 tooltip。
- 主工作区优先，不让边栏抢空间。

阅读器：

- PDF 或正文是主角。
- 右侧面板是工作抽屉，不应喧宾夺主。
- 工具栏要紧凑。
- 标注工具可见但不占大量空间。
- 专注模式应最大化阅读区域。

文献库：

- 表格要高效，但减少硬线条。
- 标签墙和详情面板要服务筛选和回跳。
- 批量操作不要长期占用核心空间。

AI：

- AI 是辅助面板或独立场景。
- 不应抢阅读器主区域。
- 回复要能显示当前上下文来源。

设置：

- 设置页按卡片或分组组织。
- 不应和主工作流一样高密度。

## 4. 视觉规范

颜色：

- 需要建立 token，避免到处写散的 `rgba(...)` 和硬编码色值。
- 不能只依赖绿色/灰绿色一套色。
- 状态色要清楚区分：成功、警告、危险、信息。

字号：

- 工作区正文优先 13px 到 14px。
- 面板标题 12px 到 13px。
- 场景标题 18px 到 22px。
- 不用超大字体，除非是空状态。

间距：

- 工具栏和表格保持紧凑。
- 阅读区周围留出稳定呼吸空间。
- 面板内部用统一 gap，不靠随意 margin。

圆角：

- 工具类界面圆角控制在 6px 到 10px。
- 不要把所有元素做成大圆角。

阴影：

- 阴影只用于浮层、弹窗、抽屉和需要层级的面板。
- 不要给每个普通块都加明显阴影。

线条：

- 少用强边框。
- 分隔优先用浅底色、间距、状态和层级。

## 5. 组件规范

应逐步在 `src/shared/ui/` 建立：

```text
Button
Panel
Dialog
Toolbar
SegmentedControl
EmptyState
IconButton
Field
```

新增 UI 时优先复用 shared 组件。没有 shared 组件时，可以先在 feature 内实现，但如果第二个模块也需要，应抽到 `shared/ui`。

## 6. CSS 组织

当前 `src/ui/styles.css` 较大，后续建议拆成：

```text
src/ui/styles/
  tokens.css
  base.css
  layout.css
  components.css
  library.css
  reader.css
  settings.css
```

拆分原则：

- token 和基础元素放全局。
- feature 专属样式放 feature 文件。
- 通用组件样式放 components。
- 不要让一个 CSS 文件长期超过 300 行。

## 7. 可用性规则

- 所有重要操作必须有 disabled / hover / active 状态。
- 危险操作必须确认。
- 导入、保存、删除、备份、恢复要有状态反馈。
- 键盘快捷键不能和输入框冲突。
- 长文本必须省略或换行，不能溢出。
- 小屏和窄窗口下不能遮挡 PDF 主内容。

## 8. 当前 UI 调整优先级

1. 修复明显乱码。
2. 建立颜色、间距、圆角、阴影 token。
3. 拆 `styles.css`。
4. 建立 `shared/ui` 基础组件。
5. 优先打磨阅读器和文献库。
6. 再统一 AI 和设置页。
