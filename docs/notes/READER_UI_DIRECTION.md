# Aster 阅读器 UI 调整方向

本文档对应 `DEVELOPMENT_TASKS.md` 阶段 2 的 P2R-1。它只定义阅读器场景的界面方向，不做全软件 UI 改版。

## 1. 设计目标

阅读器 UI 的第一目标是让 PDF 主阅读区稳定、安静、可持续阅读。工具栏、右侧抽屉、标注入口和 AI 都应服务当前文献，而不是抢占阅读空间。

阶段 2 的视觉关键词：

```text
低噪音
高密度
专业
阅读空间优先
随手启用，用完收起
```

## 2. 布局组织

阅读器使用三层结构：

```text
顶部紧凑工具栏
主 PDF 阅读区
右侧统一阅读辅助抽屉
```

顶部工具栏只保留高频、即时影响阅读的控制：

- 原文 / 译文 / 后续并排模式入口。
- 当前译文选择。
- 缩放、适配宽度、页码跳转。
- 标注工具和颜色入口。
- 右侧抽屉开关。

右侧抽屉只保留一个容器，不为笔记、AI、标注索引、关系分别创建独立侧栏。

## 3. 右侧抽屉

右侧抽屉的产品方向收敛为三个主要 tab：

```text
笔记
AI
引用
```

当前实现中的 annotations 和 relations 都属于“引用”方向。阶段 2 可以先保持内部实现文件不强行合并，但 UI 表达和后续任务应逐步收敛到“引用”入口。

抽屉默认关闭。用户点击随手记、AI 或引用入口时打开对应 tab。关闭后主阅读区恢复最大空间。

## 4. 标注工具

标注工具是阅读器高频能力，但不应铺满顶部。

阶段 2 保留常驻入口：

- 鼠标 / 拖拽阅读。
- 高亮。
- 下划线。
- 批注。
- 便签。
- 区域框选。
- 当前颜色。

低频能力进入后续菜单或命令面板：

- 删除线。
- 自由画笔。
- 形状。
- 箭头。
- 标注筛选。
- 标注导出。

## 5. 笔记与引用

笔记面板用于当前文献的 Markdown 笔记。第一版不追求完整 Obsidian 编辑器，但需要保证：

- 可快速打开。
- 可插入标注引用。
- 标注引用显示为可识别的轻量胶囊。
- 点击引用回跳 PDF 对应页和标注。

引用 tab 用于低频索引：

- 当前文件相关标注。
- 当前文献关系。
- 可回跳的对象和引用。

标注索引不是主工作入口；用户主要应该直接在 PDF 上查看标注。

## 6. AI 面板

AI 是可收起辅助面板，不是阅读器主模式。

阶段 2 的 AI UI 规则：

- AI tab 默认不打开。
- 打开后不遮挡 PDF。
- 不自动读取当前页。
- 不强制绑定标注。
- 不在顶部工具栏放过多 AI 操作。

## 7. 视觉规则

阅读器视觉调整遵循：

- PDF 页面区域使用更少背景层和边框。
- 工具栏高度保持紧凑，按钮尺寸稳定。
- 右侧抽屉弱化阴影和背景对比。
- 标注列表行距更利于扫描。
- 当前选中、可点击和危险操作要清晰，但不使用大面积强调色。
- 阅读器样式优先进入 `src/ui/styles/reader.css`。

## 8. 不做范围

阶段 2 不做：

- 不重做全局导航。
- 不做营销式或装饰性阅读器界面。
- 不引入新的 UI 框架。
- 不做完整 docking / 多窗格拖拽。
- 不把所有标注工具一次性放到界面上。
