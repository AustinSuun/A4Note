# A4 Note 账号登录与双轨社区：研究与分期建议

- 任务：`8cc9b2c8-c54e-4604-a85d-dadf674e11f3`，spec 1。
- 执行：Arena-秋序；研究及资料访问日期：**2026-09-27**。
- 性质：供讨论的研究交付，**不是已经批准的产品方案、法律意见或已实现功能**。
- 边界：不修改应用源码，不建账户/社区服务，不迁移资料库，不采集真实用户数据，不部署、安装、推送或发布。
- 项目依据：`AGENTS.md`、`docs/notes/DEVELOPMENT_HANDBOOK.md`、`docs/notes/AI_DEVELOPMENT_PLAN.md`、`README.md`。延续本地优先与场景插件化，不让社区成为本地阅读的前置条件。

## 1. 决策摘要

**建议先验证“可信论文发现 → 中文辅助阅读 → 有来源的讨论”，并保留独立的“日常”入口。不要第一版同时建设全文云盘、泛视频推荐和实时协作。**

建议的默认体验：

1. 本地阅读、笔记、导出始终可不注册；公共发现可游客浏览。
2. “学术”和“日常”两个明确入口，各自有关注/最新；跨轨内容推荐需用户主动选择，不默认混流。
3. 首批社区能力是自愿发布的论文链接卡片、原创心得、笔记选段和小型公开合集；发布前预览，默认不带 PDF、批注截图、路径或私有引用。
4. 登录先做游客与身份抽象的原型，**经资质与合规核验后**在手机号与微信扫码间选一条主路径；邮箱作为候选备选，通行密钥作为后续安全增强。
5. 首期日常内容为文字/图片/外链；原生视频上传、直播、现金激励、私信和跨设备私有库同步后置。

这些是产品建议而非用户已经作出的决定。文末列出需要用户确认的选择。

## 2. 用户、痛点、双轨关系与证据等级

### 2.1 目标用户与待验证假设

| 群体 | 假设中的痛点 | 先验证的旅程 | 不把什么当结论 |
| --- | --- | --- | --- |
| 国内本科生/初入科研研究生 | 不知道去哪里找论文，英文术语门槛高，不能判断“新”与“好” | 选方向 → 读可追溯中文导读 → 原文 → 留一个有来源的问题 | 尚无访谈证明其愿意换平台或注册 |
| 已有阅读习惯的研究生 | 信息源分散，笔记难以安全地选择性分享 | 本地整理 → 发布选集快照 → 同行反馈 → 修订版本 | 不能默认愿意公开原始 PDF/私有笔记 |
| 科技/创作兴趣用户 | 希望在学习之外交流生活、工具、作品与梗 | 日常分区 → 关注创作者 → 自愿进入相关论文讨论 | 泛内容留存是否促进学术阅读仍未知 |
| 学长学姐/教师/社区志愿者 | 重复回答入门问题、担心署名及误引 | 专题阅读单 → 有引用的讲解 → 公开勘误 | 不假定可持续免费提供专业审核 |

**事实**：来源平台的公开文档、项目现状和官方奖项页，见第 4、8、11 节。

**设计假设**：双入口更能兼顾严肃阅读与轻松交流；本地免登录可减少强制注册反感；有上下文的问题优于泛点赞。需要原型/访谈验证，不能引用市场转化率冒充本项目结果。

**待验证需求**：用户更重视找论文、看懂论文还是分享；手机号/微信哪种完成率更高；日常内容是否挤占学术注意力；愿意公开的最小内容单位是什么。

### 2.2 两条轨道的关系

“学术”承诺来源可追溯、版本清楚、问题有上下文；“日常”允许生活、科技、创作、兴趣、玩梗，但适用同样的基本行为与版权规则。共同复用账号、关注、收藏、屏蔽、举报；**不复用一个不透明的热度总榜**。

默认打开用户上次选择的轨道。搜索先说明范围，可显式切换全站。学术页可以有低频、自愿开启的“研究者日常”模块；不把视频自动播放插入 PDF 阅读。关闭社区插件后，本地资料库继续工作。

## 3. 身份与登录比较

### 3.1 一手资料核验

- 微信官方说明把网站应用扫码登录与移动应用 SDK、公众号 H5、小程序分别列为不同能力；网站应用需要开放平台账号、相应资质与应用审核。官网还列出网站资料、审核、获取 AppID 的过程。因此不能把 Tauri 桌面程序直接当作已获准的网站应用，也不能把公众号身份自动等同于桌面账号。当前账号主体、域名、费用、回调方式与审核结果仍需实际申请前核对。[1](https://developers.weixin.qq.com/community/develop/doc/000c840489c6380d63389dbb451402?highLine=%E7%A7%BB%E5%8A%A8%E5%BA%94%E7%94%A8%EF%BC%8C%E5%AE%89%E5%8D%93%E7%AB%AF%E6%97%A0%E6%B3%95%E6%8B%89%E8%B5%B7%E6%8E%88%E6%9D%83) [3](https://open.weixin.qq.com/frame?lang=zh_CN&t=home%2Fweb_tmpl)
- 阿里云当前指引写明验证码/通知短信 0.045 元/条起，发送前涉及实名认证、短信资质、签名和模板审核；个人账号自用资质不能按企业自用签名路径直接通过报备，需考虑其推荐的短信认证产品或企业认证。不是填入一个 API key 即可上线。[1](https://help.aliyun.com/zh/sms/getting-started/get-started-with-sms)
- FIDO 的通行密钥使用非对称密钥认证，具有抗钓鱼属性；同步型与设备绑定型在恢复、设备丢失及同步平台依赖上需要分别评估。不能据此承诺所有 Windows/WebView/跨设备组合开箱即用。[2](https://fidoalliance.org/passkeys-2/) [3](https://fidoalliance.org/wp-content/uploads/2023/06/FIDO_EDWG-Spring-2023_Paper-4_-Authentication-for-Moderate-Assurance-Use-Cases_FINALv3.docx-1FINAL.pdf)

### 3.2 比较矩阵（转化/成本判断均为待验证估计）

| 方案 | 桌面路径与准入 | 上手与成本 | 安全、绑定与恢复 | 本地数据与推荐顺序 |
| --- | --- | --- | --- | --- |
| 游客/纯本地 | 不依赖外部身份平台；只看公共内容，本地功能免登录 | 摩擦最低；无验证码成本；不能据此允许匿名无限发帖 | 设备丢失恢复靠用户备份；不能承诺游客数据自动云恢复 | **始终保留**；注册不自动上传现有库 |
| 手机验证码 | 后端生成短期一次性验证码，供应商送达回执；先完成主体/签名/模板审核 | 国内用户可能熟悉；有逐次短信费、重试与反刷成本；需要实测送达率 | 单号码/IP/设备/全局预算限频，错误次数锁定；换号需二次确认、延时与审计；手机号不作公开 ID | 合规可行且访谈偏好明确时做主路径；注册不等于资料公开 |
| 微信扫码 | 候选为系统浏览器打开受审网站扫码 → HTTPS 后端换取 code → 一次性桌面回传；须审核原生桌面使用场景 | 无需键入手机号的潜在优势；需手机微信、扫码切换及平台审核；费用/周期待核验，不写死金额 | AppSecret 只在后端；校验 state、回调白名单和一次性 nonce；不同 openid/UnionID 不静默合并；解绑必须保留另一恢复路径 | 获准网站应用且桌面实验更好时采用；不能承诺一定审核通过 |
| 邮箱链接/验证码 | 后端一次性短期挑战；系统浏览器确认后回传 | 覆盖面广、供应商灵活；国内用户是否常用邮箱、投递延迟与垃圾箱待测 | 链接一次性、短有效期、限制重试；敏感操作重新认证；不能把邮箱控制权等同真实身份核验 | 可作为恢复/替代入口，但社区发帖所需身份核验另由法务决定 |
| 通行密钥 | 稳定 RP 域名，系统浏览器 WebAuthn 能力探测，完成设备间回传 | 无逐次短信费；有实现/兼容/恢复成本；不能强制不支持设备的用户使用 | 支持第二密钥/恢复码；恢复不能绕过强认证；防设备丢失、同步账号被接管 | 第二阶段增强，不作为首期唯一入口 |

登录转换实验必须测“从点击到首次有效参与”的完成率，而不只测登录按钮点击率。建议主路径成功率低于 95%、短信成本超过约定预算、或平台资质无法获批时重新选型；这些数值是**建议的试验闸门，不是行业统计**。

### 3.3 身份与资料归属协议（建议）

- 内部 `accountId` 与手机号、邮箱、微信标识分离；换绑定不换内容所有权。
- 登录 token 存系统安全存储，短期访问凭证、可撤销刷新会话；不写入 URL、日志、公开仓库或笔记正文。
- 本地库的 owner/访问权限与社区账号解耦。登录不扫描文件夹、不建立默认同步队列。
- 账号合并要同时证明两个身份、预览冲突，不因相同昵称/邮箱猜测合并。
- 注销提供导出、撤销公开内容和会话、备份清理说明；法律要求保留的记录单独说明依据与期限。不能承诺别人已经合法下载/引用的内容会从全网消失。
- 未登录可读公共信息；发帖/评论的身份核验强度由所在地服务性质与合规审查决定。邮箱/微信 OAuth 不能直接当作满足全部实名要求的证明。

## 4. 学术发现：数据源与取舍

**arXiv 足以构建预印本“最新”流，但不能单独提供跨领域全覆盖、同行评审质量或会议正式奖项。**“热门”必须由可解释的站内信号另行构建，不能把 arXiv 分类等同官方热榜。

| 来源 | 适合取得什么 | 更新与采集建议 | 授权/限制/不能保证 |
| --- | --- | --- | --- |
| arXiv API / RSS / OAI-PMH | 标题、作者、摘要、ID、分类、版本及论文链接 | 我方拟每日增量，活动期分批缓存；显示来源发布时间与采集时间 | 描述性元数据 CC0；legacy API 每 3 秒最多 1 请求且单连接，所有自有机器合计遵守；PDF 再分发另看每篇授权，不因可下载就镜像。官方无本项目 SLA。[1](https://info.arxiv.org/help/api/tou.html) |
| CVF / CVPR 官方会议页 | 视觉论文、会议日程/展示类别与官方奖项证据 | 按年度会议适配，结果发布期间人工核验；不假设统一 API | 2025 官方奖项页明确列 Best Paper、Best Student Paper、Honorable Mention；不同奖项不合并。全文/图片再用需独立检查许可。[1](https://cvpr.thecvf.com/Conferences/2025/BestPapersDemos) |

| NeurIPS 官方程序/奖项页；OpenReview API V2 | ML/RL/理论会议论文与正式标签；OpenReview 只处理公开可见实体 | 各 venue 独立字段映射，官方发布后验证；公开 API 作为候选，不默认所有提交/评审公开 | NeurIPS 官方页面可单独验证 Best Paper 与 Oral；OpenReview 有 V2 文档但公开权限/下载成功率不能从文档存在推断。[2](https://neurips.cc/virtual/2025/awards_detail) [API V2](https://docs.openreview.net/reference/api-v2) |
| Crossref REST | DOI、书目信息、出版及关联元数据；用于去重与补全 | 按 DOI 缓存、增量更新，使用可联系的 mailto polite pool | 官方 2025-12-01 新规则区分单记录/列表：public 5/1 req/s、并发 1；polite 10/3 req/s、并发 3。上线继续读响应头及 429 退避，不沿用旧统一阈值。[规则原文](https://www.crossref.org/blog/announcing-changes-to-rest-api-rate-limits/) [1](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/) |
| OpenAlex | 文献/作者/机构关联及检索，作为跨学科补充 | 先用免费 key 小样本评估，缓存列表；预算闸门与失败降级 | 当前官方免费 key 预算为每天 1 美元额度，端点计价不同，不能笼统写“无限免费 API”；全量快照与接口成本区别对待。[1](https://developers.openalex.org/api-reference/authentication) [2](https://developers.openalex.org/guides/authentication) |
| DBLP（待补核验） | 候选：计算机领域书目与会议系列导航 | 未进入 MVP 必需依赖 | 本次打开 FAQ 返回 Anubis 人机挑战，未绕过。当前许可、批量下载方式和配额未完整核验，不能承诺已接入或可稳定抓取。[访问入口](https://dblp.org/faq/1474677.html) |

表中“每日”等为**我方设计刷新计划**，不是数据源承诺。第三方限流变化、页面结构变化、来源停机都必须可降级。论文正文、摘要、元数据、代码仓库许可证分开记录；单一源的开放许可不能推广到其他源。

### 4.1 三方向导航示例

以下用**可核验的 2025 历史样本**展示模型，不冒称为 2026 最新榜单。

1. **视觉 → 三维重建/几何**：arXiv `cs.CV` 最新版本流 → CVPR 年度筛选 → `VGGT: Visual Geometry Grounded Transformer` 标记为 **CVPR 2025 Best Paper**。只有官方页明确记录的奖项才亮徽标；不能由 Best Paper 反推某种 Oral/Highlight 身份。[1](https://cvpr.thecvf.com/Conferences/2025/BestPapersDemos)
2. **自然语言 → 可靠性/幻觉**：arXiv `cs.CL` + ACL Anthology → `HALOGEN: Fantastic LLM Hallucinations and Where to Find Them` 的官方 **ACL 2025 Outstanding Paper** 标签。不得翻译成 Best Paper 或 Spotlight。[1](https://2025.aclweb.org/program/awards/)
3. **机器学习 → 强化学习/自监督**：arXiv `cs.LG`/`stat.ML` → NeurIPS 年度 → `1000 Layer Networks for Self-Supervised RL: Scaling Depth Can Enable New Goal-Reaching Capabilities`，官方页同时列 **Best Paper** 与 **Oral**，分别存两条有来源的标签。[2](https://neurips.cc/virtual/2025/awards_detail)

每条路径都提供：原文标题 + 可切回英文的中文导读 + 一句“解决什么问题” + 方法/数据/局限 + 来源/版本 + 合法原文入口 + 本地阅读 + 讨论。机器生成的中文解释明确标注生成方式及不确定性，不凭模型添加实验结果；关键数字回链原论文页码。不能免费再分发无许可全文翻译。

Spotlight/Highlight 使用 `{venue, year, category, sourceURL, verifiedAt}` 独立记录；未找到官方公布就显示“未核验”或不显示，不由第三方热榜、投稿人自述、会议口头传闻推断。

### 4.2 去重、索引与可解释排序（建议）

- 统一 work 身份，版本另建 revision：DOI 规范化优先，arXiv ID 去版本用于聚合但保留 v1/v2，OpenReview forum/note ID 保留原始对应。标题+作者模糊匹配仅生成合并候选，不自动删重复。
- “最新”按来源公开时间排序，同时区分首次出现与版本更新；“热门”按滚动 7 天的**站内公开互动**排序；“官方精选”只由官方证据驱动。引用量、点赞和奖项都不是绝对质量分。
- MVP 热度建议：对去重后有效收藏、独立参与者的有来源回复做对数压缩和时间衰减；各信号权重公开。示例权重 0.5 收藏 + 0.3 有效讨论 + 0.2 独立公开阅读入口点击，仅用于实验，不使用私有 PDF 阅读记录。
- 把来源覆盖率、排序版本、时间窗口和“为什么推荐”显示出来；给新论文探索配额，防止旧热门滚雪球。用户可切到纯时间流、关闭个性化。
- 反刷：每账号/论文/窗口贡献上限、创建时间分层、异常设备/IP聚合风险信号、互赞团伙复核；不向客户端披露可利用的具体反刷阈值。自动降权需可申诉，不把学校/学历当账号可信度替代品。
- 系统性限制：未登录点击不算强热度信号；引用数据滞后，跨学科不能用绝对引用数横比；稀疏早期数据只做人工专题，不造“全网热榜”。

## 5. 自愿分享与私有资料隔离

### 5.1 可分享边界

| 对象 | 默认行为 | 允许公开的条件/风险 |
| --- | --- | --- |
| 论文链接、DOI、元数据卡片 | 优先分享链接而非文件 | 保留作者、年份、来源、版本及适用元数据许可 |
| 知识库选集 | 生成选择性、可预览的发布快照 | 不遍历整个本地库；逐项确认可见范围；私有引用显示占位，不自动上传 |
| 原创笔记/学习心得 | 只发布明确选中的段落 | 展示作者和引用，剔除本地路径、密钥、未授权人名信息与隐藏属性 |
| 标注/摘录/截图 | 默认仅发布原创评论及原文定位 | 原文长度、图像及原论文版权逐项审核；不能把个人阅读权限当传播权 |
| PDF 全文/译文 | MVP 不托管 | 只有可验证许可/权利人授权才可考虑；翻译公开涉及衍生内容权利，不由“AI翻译”免除 |
| 评论与修订 | 公共讨论围绕特定分享版本 | 旧评论绑定旧版本；撤稿/勘误有显著提示，不悄悄替换来源 |

arXiv 明确区分元数据开放使用与 e-print 再分发许可，不能把其可下载 PDF 自动镜像给社区。[1](https://info.arxiv.org/help/api/tou.html)

### 5.2 数据模型与权限建议

发布模型与本地文档分开：`localResourceId` 不直接作为公网访问凭证；发布产生 `shareId + revision + ACL + license/provenance`。第一版只支持公开/不公开，链接可见需说明“任何获得链接者可访问”，不是可靠私密权限。

公开前展示完整发布预览、资源清单与权限提示。撤销立即停止服务端公开访问并移除索引/推荐；异步清 CDN 与缓存，给出传播到第三方不可保证撤回的说明。删除保留必要的最小 tombstone，合法留存记录隔离与限权，不保留无限期全量正文作默认策略。

协作第一版采用“评论/建议 → 作者采纳 → 新版本”，不同时引入实时多人编辑和私有库同步。私人正文不进入公共检索索引、不自动作为 AI 训练/推荐特征；云同步另需单独产品与安全评审。

## 6. 日常社区与运营边界

分类建议：学习生活、工具与科技、个人创作、轻松玩梗、兴趣小组。带学术结论的帖子即使在日常区，也须支持来源标注和错误更正。反对羞辱、骚扰、歧视、开盒和恶意造谣；幽默不是侵权/骚扰豁免。

MVP：文字/图片/链接帖、评论、收藏、关注、屏蔽、举报与申诉；默认不做私信、匿名树洞、直播、打赏、现金拉新、自动播放视频。

| 能力 | 首期决定建议 | 运营/技术门槛 |
| --- | --- | --- |
| 视频 | 先允许合规外链，不默认自动拉取或转存 | 原生上传需转码/封面/字幕、流量预算、版权投诉、违法内容识别、人工复核与适龄评估 |
| 激励 | 高质量读书单/有效答疑的非现金展示，贡献可解释 | 禁止以点赞数直接分现金；避免“刷量即收益”；认可勘误与负面复现 |
| 举报 | 按侵权、骚扰、隐私、垃圾/作弊、学术误导等分流 | 接收回执、处理期限、紧急隐私通道、证据限权保存 |
| 申诉 | 与初审尽量分离，允许补证据 | 留存操作审计与理由；误判恢复内容/索引，不静默封禁 |
| 未成年人 | 明确年龄适用范围与服务能力限制 | 不靠勾选“已成年”规避义务；未成年人个人信息、公开发布、欺凌保护须专项评估 |

模型可用于风险预筛，不独自裁定版权或学术真伪。学术争论与有证据的批评不能因负面观点就按骚扰删除。高风险人身信息/违法内容先限流或隔离并快速人工处置；普通质量争议优先标注、回复与勘误。

## 7. 技术边界与逐步路线

### 阶段 0：两周研究验证（当前报告之后，仍需用户授权）

- 12–18 名学生/研究者访谈、5–8 名创作者访谈；可先用不采集个人真实资料的点击原型。
- 三方向各人工维护 20 篇有来源样例；测试中英阅读路径、双入口和分享预览。
- 确认运营主体、微信/短信准入、法律顾问、预算；不申请服务或收集手机号作为本任务默认动作。
- 退出条件：用户看不懂双轨或分享权限、没有持续运营负责人时，停在本地发现工具，不扩张社区。

### 阶段 1：受控小规模 MVP（建议 8–12 周，非排期承诺）

- 本地免登录与公共发现；3 个方向、2–3 个稳定元数据源，专题/最新优先。
- 经批准的一条登录主路径；链接卡片/原创短笔记/合集，公开发布预览和撤销。
- 分开的学术/日常文字图片流；评论/关注/收藏；举报、申诉、管理审计、导出/注销与限频必须同批到位。
- 服务端独立 API 与最小关系型存储；对象存储只收授权上传内容。不是把现有 SQLite 正式库挂到公网。
- 每一项部署、域名、付费采购、迁移、SDK依赖都另行授权。

### 阶段 2：可持续性通过后（建议再 2–3 月）

扩展领域/会议适配、专题协作、版本讨论、通行密钥、精细 ACL。对中文导读建立人工抽检与数值引用检查；AI 成本超限时回退原文摘要，不展示失真的自动结论。

### 阶段 3：独立批准

视频托管、私信、创作者资金激励、跨设备私有库同步、多人实时协作均独立立项。需要新的安全、版权、合规和成本评审；不在本研究任务授权范围内。

### 技术验收门槛（建议）

- 本地离线功能与账户服务断线互不阻断；注销不删除用户本地原始笔记。
- 发布预览与实际上传对象字节/清单一致；撤销后的未授权访问返回拒绝；导出/注销可实测。
- 重试幂等、发布 version CAS、附件病毒/格式限制、对象级权限测试、防 IDOR、速率与短信预算熔断。
- 第三方 API 失败时显示来源/更新时间，不把缓存冒充最新；来源停机不导致笔记不可打开。
- 登录回调重放、会话盗用、换绑、账号合并、丢设备、备份恢复与日志脱敏均进入测试矩阵。

## 10. 验证计划、指标和待决策项

### 10.1 原型与小规模实验（建议，尚未执行）

1. 访谈：让受访者复现最近一次找论文/读不懂/想分享却没分享的经历，而不是只问“喜不喜欢社区”。不要求上传真实私有笔记。
2. 双轨原型：对比分入口与混流，测能否在 30 秒内找到本方向最新论文/日常入口；任务顺序交叉安排，避免熟悉效应。
3. 登录原型：游客先浏览、手机号、微信扫码三条路径；分别记录退出点和误解。平台审批没完成前不伪装成真实已接入登录。
4. 分享安全：给包含虚构隐私字段/本地路径的样例，检查用户能否在预览中排除。**零次意外分享**为试点硬闸门。
5. 论文卡片：匿名标注不同来源/奖项样例，检查用户能否区分最新、站内热门、官方奖项、预印本及生成导读。

### 10.2 指标口径

- 发现→阅读：分母为去重有效论文卡片曝光，分子为主动打开原文/本地阅读入口；不是后台自动预取次数。
- 有效讨论：去重讨论串中含可核验问题/证据/纠错的比例，人工抽样标注；不用回复长度替代质量。
- 日常留存：选择日常轨道用户的 D7/W4 回访，与仅学术用户分群比较；不牺牲学术阅读完成率换总停留时长。
- 隐私与信任：误公开事件、撤销成功率、来源/奖项错误率、申诉改判率、解释理解率。
- 运维：有效短信单次登录成本、每千次发现请求成本、审核积压时间、API失败率/缓存年龄、源失效比例。

建议试点闸门：20 人可用性测试中至少 16 人无指导完成发现→阅读，至少 18 人正确理解分享范围；出现未授权私有内容上传立即停止扩张。所有目标仅为讨论用验收阈值，不是已经实现的转化率。

### 10.3 待用户决定（按优先级）

1. 是否同意 **本地免登录 + 学术/日常双入口**，不默认混流？
2. 首批人群是研究生、本科入门还是泛科技兴趣用户？先选一个作为增长与访谈主样本。
3. 运营主体、预算上限与内容治理负责人是否具备？微信与短信审核可否开展（需要另行授权）？
4. 首期是否只做链接/原创文字图片/合集，明确排除 PDF 全文、译文托管和视频上传？
5. 中文导读以人工精选还是受控 AI 辅助为主？谁对事实错误与版权审核负责？
6. 是否愿意为社区设独立阶段闸门，而不是绑定下一次桌面版本发布？

推荐默认答案：1 同意；2 先服务国内刚入门科研学生；3 未定则只做原型；4 同意；5 少量人工策划 + 清楚标注的辅助生成；6 同意。**这些推荐尚未得到用户批准。**
